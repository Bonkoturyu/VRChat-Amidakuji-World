# 仕様書 (v1.0 ロック)

最終更新: 2026-05-15  
Status: **Locked** (v1.0開発期間中はこの仕様で進行)

## 1. コンセプト

巨大あみだくじを「自動巡回する乗り物 (カート)」に乗って体験する、PC + Android クロスプラットフォーム対応のVRChatワールド。

- 4人が同時に参加し、それぞれのスタート位置に対応したカートに乗る
- インスタンスオーナーがスタートボタンを押すと、ランダム生成されたあみだくじに従って各カートが自動巡回
- 非参加者はあみだくじ構造そのものを歩き回り、カートを追いかけて間近で観戦できる
- カートがゴールに到達すると、対応する賞品エリアにプレイヤーがテレポートされる
- ゴール手前のバリアにより、参加者(カート上)のみが賞品エリアに到達できる

## 2. プレイヤーロール

| ロール | 行動 | 制約 |
|---|---|---|
| 参加者 | カートに座って走行を体験 | 走行中は降車不可(VRトリガー退出時はリタイア扱い)、Idle中のみ着座可 |
| 観戦者 | あみだくじ構造内を自由に走り回り、カートを追いかける | ゴール手前のバリアより先には侵入不可、賞品エリアへも侵入不可 |
| インスタンスオーナー | 上記に加え、スタートボタン操作権 | `Networking.IsMaster` が true なクライアント |

## 3. ワールド構成

### 3.1 エリア構成

- **スポーンエリア**: ワールド入場時の初期位置。ルール説明パネル設置
- **エントリーエリア**: あみだくじ構造の最上部。カートの待機位置(座席4つ)、スタートボタン設置
- **あみだくじ本体**: 縦に長い、歩行可能な構造。カートも歩行者も同じ床を使用(衝突は分離)
- **ゴール手前バリア**: 各レーン下端の手前 1〜2m に設置された物理メッシュ。カートの幅だけ隙間が空く
- **賞品エリア**: ゴール後にカート上のプレイヤーのみがテレポートされる先(4ゾーン)

### 3.2 配置の方向性

あみだくじ本体は**縦置き**(高さ方向に長い)。プレイヤー(参加者・観戦者ともに)は上から下に向かって進む。観戦者はあみだくじ構造を物理的に歩いて移動するので、構造内に階段やランプが必要。

物理的な寸法・座標は [docs/scene-structure.md](./scene-structure.md) を参照。

## 4. あみだくじ生成ルール

### 4.1 構造

- 縦線本数: **4** (v1.0固定。内部実装は可変対応 → [ADR-0008](./adr/0008-4lane-scope-scalable-design.md))
- 縦線間隔: 4.0 m
- 縦線長さ: 60.0 m (=Y方向)
- 横セグメント数: 12(縦線長さを12分割、各セグメント境界で横線生成判定)
- 横線生成確率: 各セグメント境界で、各隣接縦線ペアに対し 50% で生成
- 連続横線禁止: 同じ高さで隣接する横線は同時生成しない(あみだくじの数学的制約)

### 4.2 生成タイミング

- インスタンスオーナーがスタートボタンを押した瞬間に seed が決定
- seed は `UdonSynced` で全クライアントに配布
- 各クライアントが seed から同じアルゴリズムで横線配置を再構築

詳細は [ADR-0002](./adr/0002-deterministic-rng-seed-sync.md)。

### 4.3 視覚化

- 横線はシーンに「全パターン分」事前配置、enable/disable で表示制御
- 上記制約により最大横線数は固定値(縦線4本×セグメント12 = 隣接ペア3×12 = 最大36本)

## 5. カート挙動

### 5.1 構造

- カートは GameObject。`VRC_Station` を子に持つ
- カートTransformをUdonで動かすと、座っているプレイヤーも追従
- **カートと歩行者は衝突しない**(Layer分離 or コライダー設定でレイヤー区別)
- Station 設定の詳細・走行中退出時の挙動は [ADR-0007](./adr/0007-vrcstation-transform-cart.md)

### 5.2 経路計算

スタート時に seed から各カートの通過Waypoint配列をローカルで計算する。アルゴリズム詳細は [ADR-0003](./adr/0003-precomputed-waypoint-lerp.md)。

### 5.3 移動補間

- 各セグメント間を一定速度で Lerp 移動
- 速度: **2.0 m/s** (調整可。観戦者の走行速度より少し速い設定)
- 横線通過時も同速度で水平移動
- 経過時間は `Networking.CalculateServerDeltaTime(now, raceStartTime)` で算出

## 6. ゲームフロー (ステートマシン)

```
[Idle]
  ├─ 着座イベント → 参加者登録 (最大4人、Idle中のみ可)
  └─ Masterがスタート押下 (参加者1人以上) → [Countdown]

[Countdown]  (3秒)
  └─ 3秒経過 → seed生成・配布、raceStartTime記録 → [Running]

[Running]
  └─ 全カートゴール到達 → 賞品エリアテレポート → [ResultDisplay]
  └─ VRトリガー退出はリタイア扱い、走行は継続

[ResultDisplay]
  └─ 10秒経過 → [Idle]
```

v1.0では走行キャンセル機能は実装しない。状態遷移の実装パターンは [architecture.md](./architecture.md) 参照。

## 7. UI仕様

### 7.1 着座(エントリー)

- 4つの座席に `VRC_Interact` で着座
- Idle時のみ反応、Countdown/Running/ResultDisplay中は無反応
- 着座すると `participantPlayerIds[laneIndex]` に自分のPlayerIDが書き込まれる

### 7.2 スタートボタン

- エントリーエリアに大きく配置
- `Networking.IsMaster` 時のみ押下可、それ以外はビジュアルでグレーアウト
- 参加者0人時は押下不可
- gameState が Idle 以外のときも無効

詳細な権限モデルは [ADR-0006](./adr/0006-instance-owner-start.md)。

### 7.3 結果表示

- ゴール直前または直後にカート位置の上に「Goal N」表示
- ResultDisplayステート中、エントリーエリアの掲示UIに各プレイヤーの結果(座席番号 → ゴール番号)を表示

## 8. 観戦システム

### 8.1 追いかけ式観戦(全プラットフォーム共通)

- 非参加者は **あみだくじ構造内を自由に歩行可能**
- カートが走行開始すると、観戦者はカートの直近を走って追いかけられる
- カートと歩行者は衝突しない(Layer分離)
- ゴール手前バリアにより、賞品エリアへの侵入は阻止される

詳細な判断は [ADR-0009](./adr/0009-follow-alongside-spectator.md)。

### 8.2 ゴール手前バリア

- 各レーン下端の手前 **約 1.5 m** に物理メッシュ製の壁を設置
- 壁にはカート幅(約 1.5 m × 1.5 m)分の **隙間** が空いており、カートだけが通過可能
- 隙間の高さは **0.5 m 程度に制限**(歩行者が立ったまま通れない高さ)
- カートはこの隙間を通過した瞬間にプレイヤーを賞品エリアへテレポート

物理的な配置は [docs/scene-structure.md](./scene-structure.md) §7 参照。

## 9. 同期モデル

### 9.1 Synced変数 (UdonSynced)

| 変数 | 型 | 用途 |
|---|---|---|
| `seed` | int | あみだくじ生成シード |
| `gameState` | int (enum: 0=Idle,1=Countdown,2=Running,3=ResultDisplay) | ステート |
| `raceStartTime` | double | サーバー時刻ベースのレース開始時刻 |
| `participantPlayerIds` | int[4] | 各座席に座っているプレイヤーID (-1=空) |

### 9.2 同期しない情報

- 各カートの現在位置(seed + 経過時間からローカル算出)
- 横線の状態(seedからローカル算出)
- 各クライアントのUI状態

同期最小化の判断根拠は [ADR-0005](./adr/0005-minimal-sync-variables.md)、Late Joinerシーケンスは [architecture.md](./architecture.md) を参照。

## 10. パフォーマンス目標

### 10.1 PC (Windows)

- VR HMD でスポーン地点 45 FPS 以上
- VRChat World パフォーマンスランク: **Good** 以上

### 10.2 Android (Quest 2/3/3S)

- Quest 2 で 60 FPS 以上(目標)
- VRChat World パフォーマンスランク: **Good** 以上
- ファイルサイズ: 100 MB 以下

数値バジェットの詳細は [CLAUDE.md パフォーマンスバジェット](../CLAUDE.md#パフォーマンスバジェット) を参照。
Android向け最適化制約は [ADR-0010](./adr/0010-android-in-v1.0-scope.md) を参照。

## 11. 対応プラットフォーム

- **Windows (PC)**: 対応 ✓
- **Android (Quest 2/3/3S)**: 対応 ✓
- **iOS**: v1.0 では非対応。VRChat の Android フォールバックで遊べる可能性は許容するが保証外。iOS 専用ビルドは v1.1 で検討

判断は [ADR-0010](./adr/0010-android-in-v1.0-scope.md)。

## 12. 非対応事項 (v1.0)

- iOS専用ビルド(v1.1へ)
- 20人スケール(v1.1へ)
- ランダムイベント(ボーナス・トラップ等)
- BGM(簡易効果音のみ実装。完全なBGMはv1.1)
- カスタム賞品(賞品エリアは固定)
- 走行キャンセル機能
- 多言語対応
- 観戦カメラ・スクリーン機能(廃止 → [ADR-0009](./adr/0009-follow-alongside-spectator.md))

## 13. v1.0 完了の定義

以下を全て満たした状態を「v1.0完了」とする:

1. PC + Android 両ビルドが同じ Blueprint ID で公開可能
2. 4人参加でランダムあみだくじが生成され、全カートが正しく経路を辿りゴールする
3. ゴール後に各参加者が対応する賞品エリアへテレポートされる
4. 非参加者はあみだくじ構造を自由に歩行でき、カートを追いかけられる
5. ゴール手前バリアにより、非参加者は賞品エリアへ侵入できない
6. Late Joiner が走行中・Idle中・ResultDisplay中それぞれで途中参加してもクラッシュ・状態不整合が起きない
7. PC で Good ランク、Quest 実機で Good ランク + 60 FPS 達成
8. Community Labs 公開ボタンを押下可能な状態(Trust Rank・ワールド情報・サムネイル等が揃っている)

実際のステータストラッキングは [BACKLOG.md](../BACKLOG.md) のチェックリストで行う。
