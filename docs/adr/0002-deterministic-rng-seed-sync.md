# ADR-0002: 決定論的乱数 + seed同期による横線生成

- **Status**: Accepted
- **Date**: 2026-05-15
- **Revised**: 2026-05-15 (System.Random 利用可能を反映)

## Context

あみだくじの横線はランダム生成するが、全クライアントで同じ配置が見える必要がある。実装方式の候補:

1. **A. 各横線オブジェクトの状態 (bool) を全部Sync**: 横線が数十本あるとSyncコストが嵩む
2. **B. Master側でランダム生成→結果配列をSync**: 配列同期、サイズは数十 byte 規模
3. **C. seedだけSync、各クライアントが同じアルゴリズムで再生成**: 同期は int 1個

## Decision

**C案 (seed同期 + 決定論的ローカル算出)** を採用する。

実装方針:

- Master が seed (int) を生成
- `UdonSynced` int 変数 `seed` を介して全クライアントに配布
- 各クライアントの `AmidakujiGenerator` は seed を `new System.Random(seed)` で初期化し、決定論的に横線の有無を決定
- カートの経路計算も同じseedから決定論的に行う

### PRNG アルゴリズム

**`System.Random` を採用する。**

VRChat SDK 3.7.1 (2024年9月) で Udon に `System.Random` が公開された。2026年5月時点で1年半以上の運用実績があり、決定論的seedを与えた場合に全クライアントで同一の乱数列が得られる(.NET の `System.Random` は実装が決定論的)。

横線の有無の判定は `random.Next(0, 2)` を使う(整数のみ、Double系メソッドは使わない方針を維持して環境依存リスクを排除)。

## Consequences

### Positive

- 同期トラフィック最小 (int 1個)
- Late Joiner対応も seed を受信するだけで完結
- ネットワーク不安定時もseed が届けば全状態が復元できる
- `System.Random` 利用により実装が単純化(自前PRNG実装不要)

### Negative

- 全クライアントが同一アルゴリズムを実行する前提に縛られる(将来 .NET の `System.Random` 実装が変更されると影響を受ける可能性 → 当面気にしなくてよい)

### 横線生成の決定論性確保

- `random.Next(0, 2)` で 0/1 を取り、横線有無を決定
- 連続横線禁止チェックは決定論的な後処理として実装(同じ高さで左右両方に bar が立った場合、右側を優先して左側を消す等のルールを固定)
- 生成順序は「セグメントごとに lane 0-1, lane 1-2, lane 2-3」の順で `Next` を呼ぶ。順序が変わると同じseedでも別配置になるので、コード中で固定する

## 改訂履歴

- 2026-05-15: 当初は自前 xorshift32 を想定していたが、SDK 3.7.1 で `System.Random` が利用可能になっていることを確認したため、それを採用に変更
