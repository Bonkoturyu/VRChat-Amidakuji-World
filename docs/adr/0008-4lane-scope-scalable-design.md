# ADR-0008: v1.0は4レーン固定、内部設計は可変サイズ対応

- **Status**: Accepted
- **Date**: 2026-05-15

## Context

ユーザ要望:

- v1.0: 同時参加 4〜8人
- 将来 (v1.1+): 20人スケールに拡大したい

設計の落としどころとして:

1. **A. v1.0 から 20レーン対応**: 過剰実装、テスト工数増
2. **B. v1.0 は 4レーン固定、コードもハードコード**: 後で書き直しコスト大
3. **C. v1.0 は 4レーン固定、コードは可変サイズで実装**: 配列サイズ・Prefab数だけ調整すれば拡大可能

## Decision

**C案** を採用する。

具体方針:

- レーン数を `const int LANE_COUNT = 4` で一箇所定義(GameManager または専用 Constants クラス)
- ただし配列・ループは可変サイズで書く (`for (int i = 0; i < LANE_COUNT; i++)`)
- Prefab・シーン配置は v1.0 では 4 のみ用意
- v1.1 で LANE_COUNT を変えるだけでロジック側は通る状態にする

## Consequences

### Positive

- v1.0 のテスト・チューニングは 4人に絞れる
- v1.1 拡大時の主作業は「シーン配置」と「パフォーマンス再検証」が中心になる

### Negative

- v1.1 で 20レーン化する際、Synced変数 `participantPlayerIds[]` のサイズ変更が必要 → 一度に大量の `int[]` を Sync するとサイズ制限に当たる可能性あり、要再検証
- スクリーンの俯瞰画角・縦線間隔のチューニングはレーン数変更時に再必要
- 横線生成確率も 20レーンだと再調整が必要

### v1.1 で再検討する項目

- 横線生成確率(20レーンだと横線が混雑しすぎる可能性、調整必要)
- スタートボタン押下に必要な参加者下限の設定
- 観戦デッキの広さ・配置
- 俯瞰カメラの Orthographic Size(全レーンを画角に収める)
- カート間隔と縦線間隔の物理的な整合性(密集すると見映えが悪い)

### 実装上の注意

- カート Prefab、Seat Prefab、PrizeArea Prefab はそれぞれ別 Prefab として用意し、配置だけシーンエディタで行う形にする
- HorizontalBars は `HorizontalBars[lane][segment]` の二次元配列で扱い、可変サイズに対応
